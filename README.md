# ai-presentation

Репозиторий-хранилище презентаций: исходники в HTML и их экспорт в PDF.
Используется как база референсов для новых презентаций.

## Структура

Презентации разложены **по типу документа**, внутри — **папка на проект**,
внутри неё — **папка на период**. Так сразу видно, где отчёты, где аудиты,
где кейсы, и вся история одного клиента лежит рядом.

```
reports/<проект>/<ГГГГ-ММ>/           — ежемесячные отчёты
reports/<проект>/README.md            — паспорт проекта: как устроен его отчёт
audits/<проект>/<ГГГГ-ММ>-<тема>/     — аудиты (рекламного кабинета, аккаунта…)
cases/<проект>/<ГГГГ-ММ>-<тема>/      — кейсы для портфолио

shared/
  css/deck.css          — дизайн-система: слайды 16:9, Inter, акцентный цвет
  js/deck.js            — навигация по слайдам (стрелки, точки, фуллскрин, печать в PDF)
  fonts/inter/          — свои статичные файлы Inter (не Google Fonts, см. ниже)
  brand/303cult/        — логотип агентства 303.cult
  brand/clients/<проект>/ — логотипы клиентов
  templates/slide-deck.html — стартовый шаблон новой презентации
  blocks/               — каталог готовых слайдов-блоков — собирать деку из них, не с нуля
  references/           — исходники референсов, из которых собрана дизайн-система
scripts/
  inline-deck.mjs       — собирает самодостаточный <имя>.html для отправки
  export-pdf.mjs        — экспортирует <имя>.pdf
  deck-path.mjs         — общая логика путей и имён файлов
```

### Что лежит в папке одной презентации

```
reports/easyhealth/2026-09/
  index.html                        — исходник: его правим, его копируем в следующий месяц
  assets/                           — картинки, которые показываются на слайдах
  source/                           — исходные данные: выгрузки кабинета, скриншоты статистики
  easyhealth-report-2026-09.html    — готовый файл для отправки (всё встроено)
  easyhealth-report-2026-09.pdf     — готовый PDF
```

### Как называются файлы

Готовые файлы всегда называются **`<проект>-<тип>-<период>`**, где тип —
`report`, `audit` или `case`. Имя собирается скриптами автоматически из
пути папки, вручную его придумывать не нужно:

| Папка | Готовые файлы |
|---|---|
| `reports/easyhealth/2026-09/` | `easyhealth-report-2026-09.pdf` / `.html` |
| `audits/superqr/2026-09-meta-ads/` | `superqr-audit-2026-09-meta-ads.pdf` / `.html` |
| `cases/easyhealth/2026-12-whatsapp-leads/` | `easyhealth-case-2026-12-whatsapp-leads.pdf` / `.html` |

Правила имён: латиница в нижнем регистре, слова через дефис, период —
`ГГГГ-ММ` (месяц, за который отчёт; для отчёта за 27.08–27.09 это `2026-09`).
Имя проекта одно и то же во всех типах документов (`easyhealth`, а не
`easy-health` в одном месте и `eh` в другом).

## Дизайн-система (`shared/css/deck.css`)

Слайд 16:9 (1280×720), только светлый фон — белый (`.slide`) или лёгкий
голубой тон (`.slide.tint`) для ритма между разделами. Шрифт Inter —
свои статичные файлы в `shared/fonts/inter/` (не Google Fonts: сеть не
нужна ни для просмотра, ни для печати, и не оставалось шансов, что
PDF получит не тот шрифт, что HTML — см. «Экспорт в PDF»). Единственный
акцентный цвет `--accent` (по умолчанию синий `#2563EB`, меняется в
`:root` конкретной презентации при необходимости).

Основные блоки разметки — см. живые примеры в `shared/templates/slide-deck.html`
и в любой готовой презентации:

- `.top-row` / `.top-meta` — тонкая шапка слайда (раздел презентации)
- `.kicker` + inline `<svg class="i">` — пилюля-ярлык с иконкой над заголовком
- `h1.headline` (+ `.xl` для титульного) — заголовок, `<span class="accent">` — акцент
- `.lede` — подзаголовок-пояснение
- `.cols.cols-2/3/4` — колоночная сетка
- `.card` + `img.shot` — скриншот-доказательство в рамке
- `.callout` — блок «Рекомендация» с акцентной линией слева
- `.step-num` / `.item-title` / `.item-desc` — пронумерованный пункт
- `.stat-big` / `.stat-label` — крупная цифра для акцента на цифрах/деньгах
- `ul.plain` — список с маркерами `✓` / `→`
- `table.clean` — таблица метрик
- `.bottom-row` — нижняя строка: вывод слайда слева, номер `NN / всего` справа

Диаграммы вместо текстовых колонок, где нужно визуализировать, а не
перечислить:

- `.split-track` / `.split-fill` / `.split-legend` — доля от целого
  (например, «5% бюджета уходит не туда»), обычно рядом со `.stat-big`
- `.flow` / `.flow-node` (+ `.done` для «уже есть» и `.node-icon`) /
  `.flow-arrow` — цепочка узлов: воронка, сравнение «сейчас/рекомендуется»
- `.stepper` / `.stepper-line` / `.stepper-dot` (+ `.active`) — этапы
  плана на одной шкале

Все три собраны по гайду `dataviz`: один акцентный цвет на нейтральном
фоне, подписи текстом (не только цветом), статус различается и цветом,
и формой (галочка vs пунктирный круг).

Презентация на этой системе одновременно:
- **интерактивный слайд-шоу** при открытии `index.html` в браузере (стрелки,
  точки-навигация, `F` — полный экран, кнопка «PDF» — печать)
- **готовый к печати документ** — `@media print` в `deck.css` разворачивает
  все слайды в PDF-страницы 13.333×7.5in (то же 16:9)

## Новый ежемесячный отчёт по существующему проекту

1. Открыть паспорт проекта `reports/<проект>/README.md` — там структура
   отчёта, цвета, определения метрик и что обязательно повторить
2. Скопировать папку прошлого месяца целиком:
   `cp -r reports/easyhealth/2026-09 reports/easyhealth/2026-10`
3. Удалить из копии старые готовые файлы (`*-report-*.pdf/.html`) и `source/`,
   положить в `source/` новые выгрузки и скриншоты
4. В `index.html` обновить цифры, скриншоты в `assets/`, даты и выводы —
   структуру слайдов и оформление сохранить как в прошлом месяце
5. Собрать готовые файлы (см. ниже) и дописать в паспорт проекта, что
   поменялось в этом месяце

## Новый проект / аудит / кейс

1. Создать папку `<reports|audits|cases>/<проект>/<период>/`
2. Скопировать `shared/templates/slide-deck.html` в неё как `index.html`
   и поправить пути к `shared/` (`../../../shared/...`)
3. Собрать слайды из **[каталога блоков](shared/blocks/README.md)** —
   для каждого слайда взять готовый паттерн (титул, доказательство со
   скриншотом, диаграмма, roadmap, таблица метрик…) и подставить свой
   текст/картинки/числа, а не писать разметку заново
4. `assets/` — картинки для слайдов, `source/` — исходные данные
5. Для нового клиента в отчётах — завести паспорт `reports/<проект>/README.md`,
   логотипы положить в `shared/brand/clients/<проект>/`

## Сборка готовых файлов

```bash
npm install                                   # один раз, поставит playwright
npx playwright install chromium               # один раз, поставит браузер
npm run build -- reports/easyhealth/2026-09   # -> easyhealth-report-2026-09.html + .pdf
```

По отдельности: `npm run bundle -- <папка>` — только HTML,
`npm run export -- <папка>` — только PDF.

`index.html` подключает `shared/css/deck.css` и `shared/js/deck.js` по
относительным путям, поэтому работает только внутри репозитория. Для
отправки клиенту всегда брать собранный `<проект>-<тип>-<период>.html`:
в нём CSS, JS, шрифты и картинки встроены, он открывается где угодно и
рендерится один в один как PDF. Исходник `index.html` при сборке не
меняется.

Вручную PDF: открыть `index.html` в Chrome, нажать «🖨 PDF» в правом верхнем
углу (или Ctrl/Cmd+P) → Destination: Save as PDF → в More settings включить
«Background graphics».

Раньше здесь был подводный камень: шрифт с Google Fonts не всегда
успевал догрузиться к моменту печати, и PDF получался с другим шрифтом,
чем HTML. Решилось встраиванием шрифта (см. «Дизайн-система» выше) —
сети при экспорте больше не нужно вовсе. Второй, менее очевидный нюанс:
переменный шрифт (один файл на все начертания) на экране показывается
верно, но у Chromium/Skia печатный движок не всегда корректно встраивает
именно переменные шрифты в PDF и всё равно откатывается на системный —
поэтому в `shared/fonts/inter/` лежат статичные файлы, отдельные на
каждое начертание (400/500/600/700/800/900).
